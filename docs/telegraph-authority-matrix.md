# Telegraph authority matrix

Last reviewed: 2026-08-16

This matrix prevents the protocol whitepaper, Hackathon 1 instructions, and
local engineering assumptions from being merged into one unverified contract.

| Topic | Whitepaper / protocol concept | Hackathon 1 authority | OathCast implementation rule |
|---|---|---|---|
| Miner registration | Permissionless on-chain registration; the whitepaper describes Intent IDs, fee address, price floor, credential/schema metadata, and output mapping. | Registration is live and permissionless. The live portal validates YAML, sandbox-tests endpoints, pins the YAML, and submits `registerMiner` on Base Sepolia. | Keep the raw-YAML digest and transaction inputs explicit. Recheck slug availability before requesting confirmation to connect/sign; inspect the numeric routing ID conservatively, but do not confuse it with the sequential on-chain `registrationId` or treat it as an official uniqueness gate. Never infer registration from a local validator pass. |
| Miner price | 0.01 USDC protocol floor in the whitepaper. | Live docs set the minimum at `10000` micro-USDC; price is a registration transaction input, not required inside the Miner YAML. | Store and validate integer micro-USDC at the registration boundary; default the unsigned draft to the exact floor. |
| Payment | x402 challenge, wallet authorization, Telegraph verification, routing, and receipt. | Current official docs list x402 v2 payment through the HTTPS dev node with Base Sepolia USDC or Solana Devnet USDC. The exact `accepts[]` entry in the received 402 challenge is authoritative for that request. | Keep using the dedicated testnet payment boundary. Pin network, asset, amount, recipient, fee payer when present, URL, Miner path, and payload before signing; independently verify settlement and retain the returned signal identity. |
| Protocol receipt | Cryptographic Signal Receipt after protocol finalization. | Current docs return `signal_hash` for a paid call and expose `GET /engine/v1/signal/{signal_hash}` for verification. Explorer visibility remains corroboration; Telegraph-side accounting is authoritative for qualification. | Keep OathCast forecast receipts, x402 artifacts, settlement evidence, and Telegraph signal records as separate linked evidence types. |
| Script Author | Permissionless WASM registration and sandbox constraints; the whitepaper mentions a Machina bond. | The current scoring guide requires exported linear memory plus `alloc(i32)->i32`, `dealloc(i32,i32)`, and `rank_answer(6 x i32)->f32`; inputs are UTF-8 pointer/byte-length pairs, blank answers score `0`, output is `[0,1]`, the standalone artifact is at most 32 MiB, and sandboxed code has no network/filesystem/shared state. `breakdown_answer` is deprecated and removed. Registration costs gas only. Live portal build `D8HL6V9WUTFV9A7Ryk0W0` targets `0x5a2324aA18613FAD4e44bDF0d6c73Ec1f6D87ff8` and calls `registerWasm(bytes32,string,string)`, selector `0xfe1e40f7`, transmitting the canonical Intent. Ahmed says a candidate must score at least `0.60` on the Intent; the corpus and aggregation are not independently documented. | The current OathCast rank-only build implements the required interface with bounded memory, no host imports/start section, and deterministic scoring. Two clean 16,292-byte builds are byte-identical, and the exact candidate at `ipfs://QmSww9z6Dp1LPitKj3HsTRY8pjNNzhwvDLiAufKxskA3P1` was independently re-fetched byte-identically. Two old-registry transactions remain historical. Corrected transaction `0x3997dfd5b514cf56b434fb4a475e6cc015e5ae9d42064073ff044bc4f67be51e` called the current registry with selector `0xfe1e40f7`, the exact hash/CID, and `WEATHER_FORECAST`; current-registry event ID `7`, entity count `7`, and matching non-empty `getWasm(7)` prove on-chain registration and Intent binding. Dashboard `wasm_count` remains `0`, and validator Stage 1, Stage 2, and the reported threshold result are unobserved. Telegraph asked the user to retry after its indexing PR merged, but no additional transaction, decoded preflight, or authorization exists. Any retry requires fresh explicit authorization. The official example scores `0.8500`, while a valid local paraphrase scores `0.5875`; this is risk, not proof of threshold failure. |
| Flow vs Workflow | Paid Intent flow ends in routing/validation/receipt; stateful orchestration belongs to the client. | Track 3 must use real Telegraph Miners and genuine requests. | Keep payment/routing in the protocol adapter and case state, decisions, and outcome resolution in the Application. |
| Mainnet / testnet | Phase 1 Base Sepolia, Phase 2 Base mainnet. | Miner registration is on Base Sepolia. Current x402 docs offer Base Sepolia and Solana Devnet payment choices; both are test environments and the received challenge determines the usable route. | No mainnet wallet, mainnet contract, escrow, or MPC path is enabled. Use only a dedicated testnet wallet for explicitly authorized paid canaries. |

Sources: [Telegraph Protocol whitepaper](https://telegraphprotocol.com/Whitepapers%20-%20Telegraph%20Protocol.pdf), [official hackathon rules](https://hackathon.telegraphprotocol.com/rules), [current Telegraph docs](https://docs.telegraphprotocol.com/docs), and the [Miner registration portal](https://integrate.telegraphprotocol.com/).
